# Comfy Cloud MCP Proxy — Research Brief

A structured map of what the proxy can reach, what pipelines it can express, how to orchestrate them, and how to ship the resulting knowledge as a Claude Code skill.

Conventions: ✅ = officially documented and stable. ⚠️ = documented but explicitly "experimental / subject to change." 🟡 = de-facto stable (used by the official frontend) but not in the OpenAPI spec. 🔴 = community / unofficial.

A note up front: Comfy Org **already ships an official MCP server** at `cloud.comfy.org/mcp` (see §5). The proxy you're building is not redundant — the official one is a research preview with significant gaps (can't run saved workflows by ID, no workflow metadata in outputs, agent-reconstructs-from-scratch). But you should design knowing it exists, and the skill should explicitly position itself against it.

---

## 1. Comfy Cloud API surface

### 1.1 Base, auth, and the headline rule

- **Base URL**: `https://cloud.comfy.org` ✅
- **Auth**: `X-API-Key` header on every request. ✅ Generated at `platform.comfy.org/profile/api-keys`. **Not a Bearer token** — passing it as `Authorization: Bearer …` will fail.
- **Subscription gate**: API access only on **Creator** ($35/mo, 7,400 credits) and **Pro** ($100/mo, 21,100 credits) tiers. The Standard ($20) and Free tiers cannot use the API at all.
- **Concurrency limits**: Creator = 3 parallel jobs, Pro = 5. Submissions beyond the cap queue automatically.
- **Runtime cap per workflow**: 30 min (Standard/Creator), 60 min (Pro). Jobs over the cap are auto-cancelled.
- **Queue depth**: up to 100 workflows queued at once.
- **GPU**: Blackwell RTX 6000 Pro, 96 GB VRAM (single class — you can't pick).
- **Headline disclaimer from Comfy Org**: *"This API is experimental and subject to change. Endpoints, request/response formats, and behavior may be modified without notice."* — bake this into the skill copy.

Authoritative sources:

- Cloud API Overview — https://docs.comfy.org/development/cloud/overview
- Cloud API Reference — https://docs.comfy.org/development/cloud/api-reference
- OpenAPI 3.0 spec (the ground truth) — https://raw.githubusercontent.com/Comfy-Org/docs/main/openapi-cloud.yaml
- Pricing — https://comfy.org/cloud/pricing

### 1.2 Endpoint inventory

Every endpoint below is from the official OpenAPI spec unless flagged. Endpoints flagged "OSS-only" are documented for **self-hosted ComfyUI** in `comms_routes` but are **not** present on Comfy Cloud — the proxy must not call them.

#### Workflows & jobs (`workflow`, `job` tags)

| Method & Path | Purpose | Notes |
|---|---|---|
| `POST /api/prompt` ✅ | Submit a workflow for execution | Body: `{ "prompt": <api-format-json>, "extra_data?": {...}, "partial_execution_targets?": ["nodeId", …] }`. Returns `{ prompt_id, number, node_errors }`. |
| `GET /api/prompt` ✅ | Current queue exec info | Returns `{ exec_info: { queue_remaining } }`. |
| `GET /api/job/{job_id}/status` ✅ | Poll job status | Returns one of `pending`, `in_progress`, `completed`, `failed`, `cancelled`. Add `waiting_to_dispatch` and `error` as also-possible values from the OpenAPI enum. |
| `GET /api/jobs` ✅ | Paginated list, filterable | Filters: `status`, `workflow_id`, `output_type` (image/video/audio), `sort_by` (create_time / execution_time), `limit ≤ 1000`. Workflow JSON omitted from list to keep payloads small. |
| `GET /api/jobs/{job_id}` ✅ | Full job detail | Includes `workflow`, `outputs`, `preview_output`, `execution_status`, `execution_meta`, and a structured `execution_error` when failed (with `node_id`, `node_type`, `exception_type`, `traceback`, `current_inputs`, `current_outputs`). **This is what your proxy should use to retrieve outputs after polling-success — it's the canonical "get me everything about this job" call.** |
| `GET /api/queue` ✅ | `{ queue_running: [...], queue_pending: [...] }` | Items are tuple arrays `[job_number, prompt_id, workflow_json, output_node_ids, metadata]`. |
| `POST /api/queue` ✅ | Cancel pending jobs | Body: `{ "delete": ["prompt_id", …] }` or `{ "clear": true }`. **Only affects pending jobs.** |
| `POST /api/interrupt` ✅ | Cancel **running** jobs | Distinct from `/api/queue`. Affects all running jobs for the authed user. |
| `GET /api/history_v2` ✅ | Execution history (lightweight) | Workflow stripped from `extra_pnginfo`. Pagination via `max_items`, `offset`. |
| `GET /api/history_v2/{prompt_id}` ✅ | Full history for one prompt | Returns a dict keyed by `prompt_id`. |
| `POST /api/history` ✅ | Manage history | `{ "delete": [...] }` or `{ "clear": true }`. |

#### Inputs & outputs (`file`, `asset` tags)

| Method & Path | Purpose | Notes |
|---|---|---|
| `POST /api/upload/image` ✅ | Multipart image upload | Fields: `image` (file), `overwrite`, `subfolder`, `type`. **`overwrite` and `subfolder` are accepted-but-ignored** — Cloud uses content-addressed (hash-based) storage. Returns `{ name, subfolder, type }`. |
| `POST /api/upload/mask` ✅ | Multipart mask upload | Requires `original_ref` JSON string referencing the image being masked. Returns mask metadata including layer hashes (`mask`, `paint`, `painted`, `painted_masked`). |
| `GET /api/view` ✅ | Retrieve a generated file | **Returns 302 redirect to a signed GCS URL.** Client must follow redirects. Auth header on the `/api/view` request only — don't forward `X-API-Key` to the signed URL. Supports `channel=rgb\|alpha` to split PNG channels server-side. `subfolder` ignored. |
| `GET /api/files/mask-layers?filename=…` ✅ | Resolve all 4 related mask layers from any one hash | For mask-editor round-trips. |
| `GET /api/assets` ✅ | List user assets | Filter by `include_tags`, `exclude_tags`, `name_contains`, `metadata_filter` (JSON), pagination, sort by `name\|created_at\|updated_at\|size\|last_access_time`. |
| `POST /api/assets` ✅ | Upload new asset (multipart) **or** import from URL (JSON) | URL mode: `{ url, name, tags?, user_metadata?, preview_id? }`. Returns existing asset if hash matches (200), else 201. |
| `POST /api/assets/from-hash` ✅ | Create asset ref from existing hash | Lets you reference a known blob without re-uploading. Hash must be `blake3:` or `sha256:` prefix + 64 hex. |
| `GET /api/assets/remote-metadata?url=…` ✅ | HEAD-like metadata preview | Supports Civitai and other repos. Returns content_length, content_type, suggested filename, preview as base64 data URL, and a `ValidationResult` (e.g. rejects PickleTensor). |
| `POST /api/assets/download` ✅ | Background download from Huggingface or Civitai | Returns 200 with asset if already cached, or 202 with `task_id` to poll via `GET /api/tasks/{task_id}`. **This is how the proxy should bring in user LoRAs / models.** |
| `GET\|PUT\|DELETE /api/assets/{id}` ✅ | CRUD on asset | Update accepts `name`, `tags`, `mime_type`, `preview_id`, `user_metadata`. |
| `POST\|DELETE /api/assets/{id}/tags` ✅ | Add / remove tags | |
| `HEAD /api/assets/hash/{blake3:…}` ✅ | Existence check by hash | |
| `GET /api/tags` ✅ | List all tags with usage counts | |
| `GET /api/assets/tags/refine` ✅ | Tag histogram for a filtered asset set | |

#### Reference (`node`, `model` tags)

| Method & Path | Purpose | Notes |
|---|---|---|
| `GET /api/object_info` ✅ | **All** installed node definitions | Returns `{ "<class_type>": NodeInfo, … }`. NodeInfo includes `input` (with required/optional split and per-input config like `min`/`max`/`step`/`default`), `output`, `output_is_list`, `output_name`, `category`, `description`, `python_module`, `deprecated`, `experimental`, `api_node`. **This is your single most important introspection endpoint** — the entire workflow-builder logic should be driven by it. |
| `GET /api/object_info/{node_class}` 🟡 | Single-node details | Documented for OSS in `comms_routes`; the OpenAPI spec only lists the collection endpoint, but the convention `/api/object_info/<class>` is what the JS frontend uses. Treat as stable-by-convention; fall back to filtering the full payload if it 404s. |
| `GET /api/experiment/models` ⚠️ | List model folders | Replaces legacy `/models`. Returns `[{ name, folders[] }]`. Public (no auth required). |
| `GET /api/experiment/models/{folder}` ⚠️ | List models in a folder | e.g. folder=`checkpoints`, `loras`, `vae`, `upscale_models`, etc. Returns `[{ name, pathIndex }]`. |
| `GET /api/experiment/models/preview/{folder}/{path_index}/{filename}` ⚠️ | WebP model preview | |
| `GET /api/features` ✅ | Server feature flags | `supports_preview_metadata`, `max_upload_size`, more. Optional auth. |
| `GET /api/workflow_templates` ✅ | Workflow templates (public) | Currently empty object on Cloud — community templates live on `comfy.org/workflows`. |
| `GET /api/global_subgraphs` ✅ | Subgraph blueprints (public) | Map of subgraph IDs to metadata; `GET /api/global_subgraphs/{id}` returns full data. |

#### Account & system (`user`, `system` tags)

| Method & Path | Purpose | Notes |
|---|---|---|
| `GET /api/user` ✅ | Current user info | Returns `{ status: "active" \| "waitlisted" }`. |
| `GET\|POST\|DELETE /api/userdata`, `/api/userdata/{file}` ✅ | Per-user JSON/file scratch storage | Used for saved workflows, settings. `split` and `full_info` query params accepted but ignored. |
| `GET /api/system_stats` ✅ | Versions + device info (public) | Includes `comfyui_version`, `comfyui_frontend_version`, `cloud_version`, `pytorch_version`, devices with `vram_total` / `vram_free`. **Useful for the proxy to log/version-stamp every run.** |

#### WebSocket

- **URL**: `wss://cloud.comfy.org/ws?clientId={uuid}&token={api_key}` ✅
- `clientId` is "currently ignored — all connections for a user receive the same messages. Pass a unique clientId for forward compatibility."
- Always filter incoming messages by `data.prompt_id === yourPromptId` before reacting — you'll see traffic for other concurrent jobs.

JSON message types (per OpenAPI WebSocket schemas):

| Type | Payload essentials | Use for |
|---|---|---|
| `status` | `data.status.exec_info.queue_remaining` | Queue-depth UI |
| `execution_start` | `prompt_id` | Mark "started" |
| `execution_cached` | `prompt_id`, `nodes: [...]` | Skipped (cache hit) node IDs |
| `executing` | `prompt_id`, `node` (null = workflow finished), `display_node` | Per-node progress |
| `progress` | `prompt_id`, `node`, `value`, `max` | Sampling steps |
| `progress_state` | `prompt_id`, `nodes: { id: { class_type, … } }` | Richer multi-node state |
| `executed` | `prompt_id`, `node`, `output` | **This is where outputs land** (`output.images[]`, `output.video[]`, `output.audio[]`) |
| `execution_success` | `prompt_id` | Done |
| `execution_error` | `prompt_id`, `node_id`, `node_type`, `exception_type`, `exception_message`, `traceback`, `executed`, `current_inputs`, `current_outputs` | Structured error |
| `execution_interrupted` | `prompt_id` | User-cancelled |

Binary frames (big-endian, not JSON):

- **Type 1 — PREVIEW_IMAGE**: `[type:4B][image_type:4B][image_data:…]` (image_type 1=JPEG, 2=PNG)
- **Type 3 — TEXT**: `[type:4B][node_id_len:4B][node_id][text]` — node-attributed progress text
- **Type 4 — PREVIEW_IMAGE_WITH_METADATA**: `[type:4B][metadata_len:4B][metadata_json][image_data]` — metadata JSON has `node_id`, `display_node_id`, `real_node_id`, `prompt_id`, `parent_node_id`.

### 1.3 Cloud vs. self-hosted: what's locked down

Comfy Org publishes this table verbatim in the OpenAPI prologue:

| Field | Endpoint(s) | Cloud behavior |
|---|---|---|
| `subfolder` | `/api/view`, `/api/upload/*` | **Ignored.** Content-addressed storage (hash). Returned in responses for client-side organization. |
| `type` (input/output/temp) | `/api/view`, `/api/upload/*` | Partial — all files in tag-organized buckets, not directory-organized. |
| `overwrite` | `/api/upload/*` | **Ignored.** Identical content = same hash, always. |
| `number`, `front` | `/api/prompt` | **Ignored.** Cloud uses its own fair per-user scheduling. |
| `split`, `full_info` | `/api/userdata` | **Ignored.** Always returns full metadata. |

OSS-only routes (from `docs.comfy.org/development/comfyui-server/comms_routes`) that the proxy **must not** call against Cloud:

- `GET /embeddings`, `GET /extensions` — not on Cloud
- `GET /view_metadata/{folder}` — not on Cloud
- `POST /free` (unload models from VRAM) — Cloud manages this
- `GET /v2/userdata`, `POST /userdata/{file}/move/{dest}` — not on Cloud
- `POST /users`, `GET /users` — Cloud handles auth differently

Other Cloud-only restrictions:

- **No installing custom node packs.** Cloud ships a curated, pre-installed list (see §2.3). Comfy Cloud's own marketing: *"Most popular ones are available, and new ones are added over time."* No Manager, no ad-hoc `pip install`. Workaround: request adds via https://comfy.org/cloud/supported-nodes/ → "Submit new request".
- **No arbitrary model uploads to filesystem.** Use the Assets API (`POST /api/assets`, `POST /api/assets/download` for HF/Civitai-backed downloads).
- **No model uploads from disk on Free/Standard.** Per the Comfy Cloud FAQ: *"For those on the Creator or Pro plans, you can bring in your own fine-tuned LoRAs from CivitAI [or Huggingface]."* HF + direct file upload were listed as roadmap items in older copy; the OpenAPI now exposes `POST /api/assets/download` for both HF and Civitai, so this is shipped.
- **No filesystem access from custom code.** Every operation goes through HTTP.
- **No `extra_data.api_key_comfy_org` packaging.** Partner Nodes (Kling, Nano Banana, Ideogram, etc.) require you to put your **same** Comfy API key into `extra_data.api_key_comfy_org` inside the workflow submission — the browser frontend does this for you; the API client must do it manually.

### 1.5 Rate / size limits — what's documented vs. left vague

What's nailed down:

- Concurrent jobs: 3 (Creator) / 5 (Pro).
- Per-workflow runtime: 30 min / 60 min.
- Queue depth: 100.
- Credit burn: per-second of active GPU time. Idle (UI editing) is free.

What's **not** in any documented form (flag in the skill, suggest dynamic discovery):

- Per-endpoint REST rate limits — not published. Probe `GET /api/features.max_upload_size` for upload caps.
- No documented HTTP rate-limit headers. The proxy should treat 429 as "subscription dead", and add its own client-side throttling.
- Maximum prompt JSON size — not published. Assume ~1–10 MB is safe; large embedded image base64 will hit upload limits much sooner.

## 2. Workflow expressiveness

### 2.1 The two formats — "Workflow" vs "API" / "Prompt"

This is the source of the most common confusion and ComfyUI has explicitly chosen to keep them separate.

**API format (a.k.a. "prompt" format)** — what `/api/prompt` accepts:

```json
{
  "3": {
    "class_type": "KSampler",
    "inputs": {
      "seed": 156680208700286,
      "steps": 20,
      "cfg": 8.0,
      "sampler_name": "euler",
      "scheduler": "normal",
      "denoise": 1.0,
      "model":     ["4", 0],
      "positive":  ["6", 0],
      "negative":  ["7", 0],
      "latent_image": ["5", 0]
    }
  },
  "4": { "class_type": "CheckpointLoaderSimple",
         "inputs": { "ckpt_name": "v1-5-pruned-emaonly.ckpt" } },
  "5": { "class_type": "EmptyLatentImage",
         "inputs": { "width": 512, "height": 512, "batch_size": 1 } }
}
```

Flat dict; keys are string node IDs; values are `{ class_type, inputs }`. Links are tuples `["source_node_id", output_index]`. This is the wire format.

Hidden inputs the server injects automatically (don't put them in your JSON):

- `PROMPT` — the full graph
- `UNIQUE_ID` — current node ID
- `EXTRA_PNGINFO` — metadata dict for SaveImage
- `API_KEY_COMFY_ORG` — Partner-Node auth, sourced from `extra_data.api_key_comfy_org`

**Canvas / UI format ("workflow" format)** — what `File → Save` produces in the editor. It has additional fields the API doesn't need or accept: integer node IDs, `pos: [x, y]`, `size`, `color`, link arrays (`[link_id, from_node, from_slot, to_node, to_slot, type]`), `groups`, `extra`, `definitions.subgraphs` for the blueprint/subgraph system, and `widgets_values` (the raw widget values pre-mapping to named inputs).

**Conversion**:

- **Canvas → API** is what the frontend does internally when you press "Queue". To do it outside the browser, the cleanest path is to load the workflow into a headless frontend (the `Comfy-Org/ComfyUI_frontend` project has a `loadApiJson` / `graphToPrompt` path) or use **ComfyScript** which converts in Python (https://github.com/Chaoses-Ib/ComfyScript). Many community proxies just require API format and ban canvas format on the input boundary. **The official Comfy MCP server takes this exact stance** — it can list/inspect saved (canvas-format) workflows but cannot run them, and tells the agent to reconstruct from scratch.
- **API → Canvas** is one-way lossy (positions, widget orderings are guessed). Glama publishes one reference for this conversion at https://glama.ai/mcp/servers/@IO-AtelierTech/comfyui-mcp/tools/save_workflow.
- **Drag-and-drop reload**: the canvas format is embedded in PNG `EXTRA_PNGINFO` and in video container metadata, which is why you can drag a generated PNG back onto the canvas. The Cloud MCP server explicitly notes that *"images created via the MCP server don't include workflow JSON in their metadata"* — a gap your proxy can close by always SaveImage'ing with `extra_pnginfo` populated.

For the formal schema, see https://docs.comfy.org/specs/workflow_json (canvas format) and the DeepWiki summary of the API format at https://deepwiki.com/Comfy-Org/ComfyUI/7.3-workflow-json-format. There's an open RFC for a formal JSON Schema of the prompt format (https://github.com/comfyanonymous/ComfyUI/issues/8899) — not merged yet, so flag in the skill that schema validation is best-effort.

## 3. Orchestration patterns

### 3.1 The prompt lifecycle

```
POST /api/prompt → { prompt_id }
   ↓
WebSocket: execution_start { prompt_id }
   ↓
WebSocket: execution_cached { nodes: [...] }   // optional
   ↓
WebSocket: executing { node }                  // per node
   ↓                ↓
WebSocket: progress      WebSocket: executed { node, output }
   ↓
WebSocket: execution_success | execution_error | execution_interrupted
   ↓
GET /api/jobs/{prompt_id} → outputs (or accumulate from executed events)
   ↓
For each output file: GET /api/view?filename=...&type=output (follow 302) → download
```

Two patterns for monitoring:

1. **Polling** — simpler, idempotent, but coarse. Hit `GET /api/job/{prompt_id}/status` every 1–3s; on `completed`, call `GET /api/jobs/{prompt_id}` for the full `outputs` object.
2. **WebSocket** — required if you want progress, previews, or to chain workflows the moment the previous one finishes. Always filter `if (data.data?.prompt_id !== myPromptId) return;` because Cloud broadcasts all of a user's events to all of that user's open sockets (the `clientId` param is currently a no-op).

A **hybrid** is what most production code lands on: open a WebSocket for progress/previews and chaining, but use `GET /api/jobs/{id}` to authoritatively fetch the final output set (because WS messages can be dropped and the REST endpoint always has the canonical outputs once `execution_success` fires).

### 3.2 Programmatic workflow generation — `/api/object_info` as the schema source

ComfyUI doesn't ship a static prompt JSON Schema — the schema is derived live from `/api/object_info`. Every node's `INPUT_TYPES` declaration becomes a `NodeInfo.input` object with required/optional keys and per-input config (`min`, `max`, `step`, `default`, an enum list for combos). This is what powers the JS frontend's UI generation and what tools like ComfyScript use.

Standard introspection-driven workflow build:

1. On startup, fetch `GET /api/object_info` once and cache. Index by `category` and by `class_type`.
2. To build a node, look up `inputs.<input_name>` to know what type and value range is legal.
3. For combo inputs (model names, schedulers, sampler_names), the legal values are the array under `input[<name>][0]` — these are dynamic per Cloud (e.g. which checkpoints are installed).
4. Render the workflow as the flat `{ id: { class_type, inputs } }` dict.

Projects that do exactly this and are worth citing in the skill:

- **ComfyScript** (https://github.com/Chaoses-Ib/ComfyScript) — Python AST that generates valid API-format JSON, with type hints and auto-discovery from `/api/object_info`.
- **comfy-cli** (https://docs.comfy.org/comfy-cli/getting-started) — official CLI, useful prior art for env discovery.
- **ComfyUI_frontend** (https://github.com/Comfy-Org/ComfyUI_frontend) — the actual graph-to-prompt code lives here; `window.app.graphToPrompt` is the in-browser conversion function and `loadApiJson` accepts API format.

### 3.3 Parameter sweeps, seeds, determinism, A/B

- **Seed continuity**: set a fixed seed across runs. Use `seed: <int>` rather than `-1` / `random`. The KSampler node accepts `control_after_generate: "fixed" | "increment" | "decrement" | "randomize"` — use `"fixed"` for deterministic regeneration.
- **Parameter sweep**: submit N workflows in parallel up to the concurrency cap (3 Creator / 5 Pro). The Cloud overview's own example shows this pattern:
  ```python
  for seed in [42, 123, 456]:
      workflow["3"]["inputs"]["seed"] = seed
      submit_workflow(session, workflow)
  ```
- **A/B variant generation**: identical workflow + only the variant input changed. The proxy should compute a content hash of the workflow JSON (sorted keys, stable serialization) and use that as a cache key. Cloud's content-addressed storage gives you idempotency for free on the *output* side but not the *request* side.
- **Caching identical prompts**: Cloud reports cached node outputs via the `execution_cached` WebSocket message. Don't double-cache server-side cached results in your proxy.
- **Asset registry**: lean on the Assets API tags (`POST /api/assets/{id}/tags`) instead of building a parallel registry. Tag uploaded inputs with e.g. `["proxy:project=foo", "proxy:run=2026-05-21T10:00:00Z"]` and search later with `?include_tags=proxy:project=foo`.

### 3.4 Guardrails for exposing this to an LLM agent

What the proxy MCP layer should enforce (none of these are provided server-side):

| Risk | Guardrail | Where |
|---|---|---|
| Runaway cost | Pre-flight cost estimate. Multiply step count × known per-step seconds for the chosen model. Block if estimated > user-set credit budget. | Proxy, before `POST /api/prompt` |
| Concurrent flood | Hard cap below tier limit (e.g. 2 of 3 on Creator) so manual UI use isn't starved | Proxy queue |
| Long-running jobs | Timeout shorter than tier cap (e.g. 20 min on Standard's 30-min cap) | Proxy poll loop |
| NSFW / content policy | Run a content classifier on input prompts and uploaded images before submission. Comfy Cloud's TOS prohibits it, but they don't filter for you. | Proxy boundary |
| Prompt injection via filenames / EXIF | Sanitize before passing to `LoadImage` / metadata | Proxy boundary |
| Partner-Node billing surprises | Detect Partner-Node `class_type`s, surface explicit estimated credit cost, require user opt-in | Proxy workflow validator |
| Custom-node-not-found | Validate every `class_type` against cached `/api/object_info` before submitting | Proxy validator |
| Failed downloads | Catch `ModelDownloadError` and `ImageDownloadError` from `execution_error`; retry with backoff on 422 | Proxy |
| Token / API-key leakage | Never include `X-API-Key` in logs; never forward it to the GCS signed URL after the 302 | Proxy |

## 4. Customization beyond the defaults

### 4.1 Multi-model pipelines

The canonical SD1.5 → SDXL refiner → 4× ESRGAN → face restoration pipeline:

```
CheckpointLoaderSimple (SD1.5)
    → CLIPTextEncode (pos/neg)
    → EmptyLatentImage
    → KSampler (denoise=1.0, ~20 steps)
    → VAEDecode
        → ImageScale (optional)
        → VAEEncode (with SDXL VAE)
            → CheckpointLoaderSimple (SDXL refiner)
            → KSampler (denoise=0.2–0.3, 10 steps)
            → VAEDecode
                → UltimateSDUpscale (model: 4x_NMKD-Siax_200k, denoise 0.2)
                    → Impact Pack FaceDetailer (yolov8 face → SAMDetector → KSampler)
                        → SaveImage
```

Practical notes: the SDXL refiner expects the base model's latents at the **same resolution**, so use `latent_image` passthrough (not `VAEDecode → VAEEncode`) where possible. The `model.unet.diffusion_model.model_type` mismatch will surface as a `ValidationError` from `KSampler` if you try to feed SD1.5 latents into SDXL UNet without re-encoding.

### 4.2 LoRA / embedding management

- **Stack syntax**: `LoraLoader` chains. Each takes `(model, clip, lora_name, strength_model, strength_clip)` and outputs `(model, clip)`. Just chain them.
- **Dynamic LoRA selection**: discover available LoRAs via `GET /api/experiment/models/loras`. For user-supplied LoRAs, `POST /api/assets/download` (HF or Civitai) then reference by filename.
- **Strengths**: model strength 0.5–1.2 is the usable range; CLIP strength often goes lower (0.3–0.8). The proxy should expose these as separate parameters in tool schemas.
- **Multi-LoRA**: chain `LoraLoader` nodes — there's no built-in "stack" node in core, but `Radiance LoRA Stack` (24-node `radiance` pack) and `Wan21 Block Lora Select` from KJNodes give ergonomic alternatives.
- **Embeddings**: reference inline with `embedding:filename` syntax inside `CLIPTextEncode.text`. Discover via `GET /embeddings` on OSS, but Cloud has dropped that route — embeddings come bundled with checkpoints on Cloud.

### 4.3 Conditioning techniques

- **Prompt weighting**: native syntax `(word:1.3)` and `(word:0.7)` works in `CLIPTextEncode`.
- **BREAK syntax**: not native ComfyUI — that's an A1111 idiom. The ComfyUI equivalent is multiple `CLIPTextEncode` nodes combined via `ConditioningCombine` / `ConditioningAverage` / `ConditioningConcat`.
- **Conditioning composition**:
  - `ConditioningCombine(a, b)` — sums them
  - `ConditioningAverage(a, b, weight)` — interpolates
  - `ConditioningConcat(a, b)` — concatenates the token sequences
- **Area conditioning**: `ConditioningSetArea` and `ConditioningSetMask` for spatial regional prompting; combine with multiple positive conditionings then `ConditioningCombine`.
- **Time-based conditioning**: `ConditioningSetTimestepRange` to apply different prompts at different sampling steps.
- **ControlNet stacking**: each `ControlNetApply` outputs new conditioning; chain them. With Advanced-ControlNet you can also schedule per-step weighting.

### 4.4 Animation / video on Cloud

Per the pre-installed node list, all of these are feasible **today**:

| Engine | Pre-installed nodes | Notes |

| **Wan 2.2 (i2v, t2v, animate)** | `ComfyUI-WanVideoWrapper` (51), `ComfyUI-WanVaceAdvanced`, `ComfyUI-WanAnimatePreprocess`, `ComfyUI-SCAIL-Pose` | Includes TeaCache/MagCache for speed, MultiTalk/FantasyTalking for talking-head, VACE module |
| **LTX-Video** | `ComfyUI-LTXVideo` (17) | Base Sampler, In-Context Sampler, Looping Sampler |

## 5. Shipping this as a Claude Code skill

### 5.1 The competitive landscape

Before designing the skill, acknowledge the official ComfyUI MCP Server at https://cloud.comfy.org/mcp:

- Hosted by Comfy Org, HTTP transport, same `X-API-Key` auth.
- Tools: `search_templates`, `search_models`, `search_nodes`, `submit_workflow`, `upload_file`, `get_job_status`, `get_output`, `use_previous_output`, `cancel_job`, `get_queue`, `list_saved_workflows`, `get_saved_workflow`.
- **Known limitations** (verbatim from the docs):
  - Cannot run saved workflows by ID — agent must reconstruct from API format.
  - Generated assets don't include workflow JSON in metadata.
  - Workflow accuracy depends on the AI building the JSON.
  - Image previews resized to 1024px.
  - API-key auth only (no OAuth yet).

The Niklaz proxy's value proposition relative to that:

- **Skill-driven workflow templates** — pre-built, validated API-format workflows that an agent can parameterize, not reconstruct.
- **Cost/runtime guardrails** before submission.
- **Local caching** of `/api/object_info` and prior outputs.
- **Asset-registry semantics** layered on top of the Assets API.
- **Custom guardrails** around Partner Nodes and NSFW.

The skill should explicitly position itself: "Use this when you need pre-validated workflow templates, parameter sweeps, deterministic regeneration, and cost guards. Use the official `cloud.comfy.org/mcp` when you want the agent to reason about arbitrary nodes/templates from scratch."

### 5.4 Specific best-practices to apply

From the official authoring guide:

- **Concise**: don't re-explain what ComfyUI is. Assume Claude knows.
- **Description is "pushy"**: enumerate trigger phrases. Anthropic's own skill-creator skill explicitly recommends this because Claude tends to undertrigger.
- **Gerund or noun-phrase naming**: `comfy-cloud-mcp` is acceptable noun-phrase form; `running-comfy-workflows` would be gerund form. Either works.
- **Third person in `description`**: "Generates, validates, runs..." not "I can..." or "You can...".
- **Bundle scripts, don't generate them on the fly**: scripts in `scripts/` are more reliable and use no context tokens until executed.
- **Workflows as checklists**: the §3.1 lifecycle is exactly the "workflow with checklist" pattern Anthropic recommends.
- **Validation feedback loops**: `scripts/validate_workflow.py` is the "validator → fix → repeat" pattern.
- **Plan-validate-execute**: for parameter sweeps, generate a sweep plan as JSON, validate it (estimated total cost), then execute. Anthropic flags this as the right pattern for "batch operations, destructive changes, high-stakes operations."
- **Avoid time-sensitive content**: don't write "as of May 2026 the Pro tier is $100". Just say "see https://comfy.org/cloud/pricing".
- **≥3 evals**: txt2img round-trip, parameter sweep with concurrency cap, and `execution_error` recovery.
- **Test on Haiku, Sonnet, Opus**: workflow JSON construction is plausibly fragile on Haiku — bias the templates and scripts so Haiku doesn't need to reason about node graphs from scratch.
